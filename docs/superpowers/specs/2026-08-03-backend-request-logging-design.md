# 后端请求日志设计

## 目标

为 FastAPI 后端的每一次 HTTP 请求生成一条结构化日志，默认写入
`backend/logs/requests.log`。日志覆盖请求与响应元数据、请求体和响应体，同时避免将密码、
令牌、Cookie、大体积内容或二进制文件原样写入磁盘。

## 日志格式与存储

- 每个已处理的 HTTP 请求写入一行 JSON Lines 记录。
- 默认日志目录为 `backend/logs/`，应用工厂允许注入其他目录，测试使用临时目录。
- 活跃文件名为 `requests.log`，单个文件达到 10 MB 后滚动，保留 5 个历史文件。
- `.gitignore` 明确忽略 `/backend/logs/`，包括活跃日志和滚动文件。
- 日志使用 UTF-8 编码，JSON 保留中文而不转义为 ASCII 序列。

每条记录包含：

- `timestamp`：UTC ISO 8601 时间。
- `client_ip`：客户端 IP；无法取得时为 `null`。
- `method`：HTTP 方法。
- `path`：请求路径，不包含查询参数值。
- `status_code`：响应状态码；应用异常按 500 记录后继续向上抛出。
- `duration_ms`：从收到请求到响应完成的耗时。
- `request_content_type` 与 `response_content_type`。
- `request_body` 与 `response_body`。

## 中间件边界

新增一个原生 ASGI 请求日志中间件，并在 `create_app()` 中注册。中间件位于 HTTP 协议边界，
通过包装 ASGI 的 `receive` 和 `send` 调用观察请求与响应数据，不消费或替换业务代码需要的
消息。这使日志覆盖正常路由、404、静态文件和未处理异常，并保持流式响应按原有方式发送。

中间件只捕获每个方向最多 16 KB 数据，并持续统计实际字节数。日志写入发生在响应完成或
请求异常之后；日志格式化或写入不改变业务响应内容。

## 请求体与响应体处理

- JSON 和 `application/*+json`：解析为结构化数据，并递归脱敏敏感字段。
- URL 编码表单：解析字段，并按相同规则脱敏。
- `text/*`：记录解码后的文本。
- `multipart/form-data`、文件下载和其他二进制内容：只记录内容类型、实际大小和
  `binary: true`，不记录字节内容。
- 空正文记录为 `null`。
- 正文超过 16 KB 时只记录内容类型、实际大小和 `truncated: true`，不保留残缺预览，
  避免无法解析的半段 JSON 绕过敏感字段脱敏。
- 无法按声明类型解码的正文按二进制内容处理，不影响请求处理。

敏感字段名按大小写不敏感方式识别，并忽略连字符与下划线差异。至少包括密码、访问令牌、
刷新令牌、Authorization、Cookie 和 Set-Cookie；对应值统一替换为 `***`。不记录请求头或
查询参数值。

## 应用集成

`create_app()` 增加可选日志目录参数。未传入时使用 `backend/logs/`，与现有数据库和上传目录
一样属于本地运行数据。测试 fixture 显式传入 `tmp_path / "logs"`，防止测试运行污染项目目录。

请求日志实现放入独立后端模块，应用入口只负责解析日志路径并注册中间件。业务路由、服务和
数据库模型无需改动。

## 错误处理

- 未处理的应用异常仍由 FastAPI/测试客户端按原有方式处理，但日志状态码记为 500。
- 日志正文解析失败时降级为安全的元数据记录，不阻断业务请求。
- 日志文件无法在应用创建时打开时让启动失败，避免服务在误以为已启用审计日志的情况下运行。
- 运行期间的请求日志写入通过 Python 日志处理器的锁串行化，避免并发请求互相拼接日志行。

## 测试边界

测试只通过公开 HTTP 接口观察行为：创建使用临时日志目录的应用，发起请求，再逐行解析
`requests.log`。

测试覆盖：

1. 健康检查和登录请求各生成一条结构化日志，证明每个请求单独记录。
2. 登录请求体保留普通账号字段，但密码为 `***`；登录响应保留普通用户字段，但访问令牌为
   `***`。
3. 超过 16 KB 的正文只记录大小与截断标记。
4. multipart 或二进制请求只记录类型与大小。
5. 404 和应用异常仍生成相应状态码日志。

完成后运行新增测试文件、完整后端 Pytest 套件，并检查 `.gitignore` 能忽略日志目录。
