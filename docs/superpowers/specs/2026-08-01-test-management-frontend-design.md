# 测试管理平台前端设计

## 目标

在前后端分离项目中构建一个完整可操作的测试管理平台前端原型。界面参考方案 1，采用深蓝固定侧栏、冷白工作区、紧凑信息密度和青绿色状态强调。所有面向用户的界面文字使用中文，HTTP 方法、URL、JSON、ID 等技术标识保留原格式。

本阶段只实现前端与本地模拟数据，不实现登录页、真实后端接口或真实 XMind 文件解析。

## 技术方案

- React 18、TypeScript、Vite
- Ant Design 作为基础组件库
- React Router 负责页面路由
- Recharts 负责仪表盘图表
- Vitest 与 React Testing Library 负责组件和交互测试
- Playwright 负责桌面端与移动端浏览器验证

不采用 Ant Design Pro 脚手架。自定义应用骨架可以减少 Umi/Max 约束，并更准确地还原参考图的密度和布局。

## 仓库边界

所有前端运行时代码、构建配置、测试、模拟数据和静态资源必须位于 `frontend/` 目录。仓库根目录只保留跨项目文档和版本控制所需文件，便于未来新增独立的后端目录。

```text
frontend/
├── public/
├── src/
│   ├── app/          # 应用入口、路由、布局、主题
│   ├── pages/        # 按页面划分的业务模块
│   ├── components/   # 跨页面复用组件
│   ├── services/     # 数据契约和数据源适配层
│   ├── mocks/        # 本地模拟数据及异步仓库
│   ├── assets/       # 图片等静态资源
│   ├── styles/       # 全局样式和设计变量
│   └── tests/        # 测试工具与跨页面测试
├── package.json
├── vite.config.ts
└── tsconfig.json
```

页面内部专用组件放在对应的 `pages/<page>/components/` 中。只有被多个页面真实复用的组件才移动到 `src/components/`。

## 全局应用壳

桌面端使用固定深蓝侧栏和固定顶部工具栏。侧栏包含：

- 仪表盘
- 测试用例，可展开功能用例、接口用例和UI自动化
- XMind 转换器
- 人员管理
- 设置

顶部工具栏包含全局搜索、通知、帮助、项目选择器和当前用户头像。示例项目名为“阿尔法测试平台”。全局搜索只过滤当前原型内的可见用例和人员，并提供中文空状态。

窄屏下侧栏折叠为抽屉导航，顶部工具栏压缩为图标和项目选择器。固定格式组件保持稳定尺寸；宽表格允许横向滚动，抽屉在移动端占满视口宽度。

## 页面与路由

### `/dashboard` 仪表盘

默认路由。页面包含：

- 用例概览：展示功能、接口、UI自动化用例数量及总数环形图。
- 导入导出中心：导出电子表格、XMind 生成用例等操作入口。
- 快捷操作：创建三种类型的用例。
- 最近用例：展示 ID、名称、类型、优先级、维护人、状态和操作。

快捷操作会导航到测试用例页的对应页签，并自动打开对应创建抽屉。导出操作生成一个前端模拟文件并展示成功反馈。

### `/test-cases/:type` 测试用例

`type` 为 `functional`、`api` 或 `ui`。页面上方使用中文页签“功能用例”“接口用例”“UI自动化”。主体为模块树和用例表格双栏布局。

- 模块树包含核心模块、鉴权、支付等节点，选择节点后过滤表格。
- 表格支持关键字、优先级和状态筛选。
- 接口用例表格展示 ID、接口地址、方法、预期状态、创建人和状态。
- 每种页签提供差异化创建抽屉。

接口用例抽屉包含用例名称、URL、HTTP 方法、可增删的请求头键值对、JSON 请求体和断言规则。JSON 输入必须通过语法校验。功能用例表单侧重前置条件、步骤和预期结果；UI自动化表单侧重页面地址、定位方式和执行环境。

创建成功后关闭抽屉、展示成功消息，并将新用例插入当前表格首行。

### `/xmind` XMind 转换器

页面采用明确的线性工作流：待上传、上传中、解析预览和解析完成。

- 上传区支持点击和拖拽，只接受 `.xmind` 文件。
- 上传中展示文件名、进度和取消操作。
- 解析预览左侧展示根节点与分支树，右侧展示到系统模块的映射。
- 用户可以重新上传或开始完整解析。

纯前端原型不解包真实 XMind 内容。任何合法扩展名文件都会进入稳定的示例预览，用于完整演示交互和状态转换；界面不会宣称已经解析真实文件内容。

### `/personnel` 人员管理

页面包含“用户列表”和“角色与权限”页签。

- 用户列表展示头像、姓名、邮箱、部门、角色、状态和操作。
- 支持搜索、角色筛选和状态筛选。
- 状态开关即时更新本地数据并给出反馈。
- 添加用户抽屉包含姓名、邮箱、部门、角色和初始密码，并执行必填、邮箱格式与密码长度校验。
- 角色与权限页签使用权限矩阵展示测试用例、XMind、人员和设置权限。

新增用户成功后出现在列表首行。头像使用确定性的姓名首字母色块，不依赖外部图片服务。

### `/settings` 设置

设置页面保留完整导航目标，展示简洁的中文占位内容和当前项目基本信息，不实现设置编辑流程。

## 数据流与边界

页面只依赖 `services` 中定义的接口，不直接读取模拟数据。服务接口返回 Promise，以便模拟加载状态并保持与未来真实请求相同的调用方式。

本地仓库维护当前会话内的可变数据：创建用例、添加用户和状态切换会即时反映到后续读取结果。刷新页面后恢复初始模拟数据，不提供持久化承诺。

路由状态承载从仪表盘发起的快捷操作，例如目标页签和是否打开创建抽屉。页面内筛选、抽屉开关和表单草稿保持局部状态，避免引入不必要的全局状态库。

## 反馈与错误处理

- 初次加载显示骨架屏，按钮提交时显示局部加载状态。
- 无结果时显示中文空状态，并保留清除筛选入口。
- 表单错误显示在对应字段附近，不只使用全局消息。
- XMind 上传校验错误说明允许的文件类型。
- JSON 语法错误阻止接口用例提交，并显示明确提示。
- 服务层保留失败结果类型；页面使用 Ant Design 消息或结果页展示失败反馈。
- 抽屉关闭前若存在未提交内容，提示用户确认放弃。

模拟服务默认成功，以保证演示流程稳定；测试通过可注入的失败实现验证错误分支。

## 视觉规范

- 主导航使用深蓝色，工作区使用冷白和浅灰背景。
- 主操作使用清晰蓝色，成功或启用状态使用青绿色，警告使用琥珀色，危险状态使用红色。
- 卡片圆角不超过 8px，页面区块不嵌套装饰性卡片。
- 页面标题保持工作台尺度；表格、抽屉和侧栏使用紧凑字号和稳定行高。
- 图标优先使用 Ant Design Icons，并为不熟悉的图标提供工具提示。
- 不使用装饰性渐变、光斑或大面积单色主题。
- 所有按钮和标签在桌面及移动端不得发生文字溢出或内容重叠。

## 测试与验证

Vitest 与 React Testing Library 覆盖：

- 默认路由和侧栏导航。
- 仪表盘快捷操作跳转并打开正确抽屉。
- 接口用例请求头增删、JSON 校验和创建成功。
- XMind 文件类型拒绝、上传进度、预览和完整解析。
- 新增用户校验、提交和状态切换。
- 移动端导航抽屉的打开与关闭。

Playwright 覆盖主要页面的真实浏览器流程，并在至少 `1440x1000` 和 `390x844` 两个视口截图检查。视觉验证重点检查：非空白渲染、侧栏与顶部栏定位、抽屉尺寸、表格可达性、中文文字不溢出、页面元素不重叠。

完成前运行单测、类型检查、生产构建和 Playwright 流程。

## 验收标准

- 所有前端代码与配置位于 `frontend/`。
- 四个核心页面和设置占位页可通过侧栏访问。
- 所有指定抽屉、页签、筛选、上传、创建和状态切换均可操作。
- 页面数据通过可替换的服务接口提供，当前使用本地模拟实现。
- 用户可见界面文字为中文。
- 桌面端与移动端均无明显溢出、遮挡或不可达操作。
- 单测、类型检查、生产构建和浏览器验证全部通过。
