# 角色权限显式保存设计

## 目标

在人员管理的“角色与权限”页签中增加显式保存能力。用户可以连续调整权限勾选，确认后统一保存；保存成功的权限写入现有角色数据，重新进入页面或刷新后仍然保留。

## 范围

- 仅保存角色权限矩阵中的权限勾选。
- 用户列表的搜索关键字、角色筛选和状态筛选不保存。
- “用户列表”页签继续显示“添加用户”；“角色与权限”页签在页面右上角显示带保存图标的“保存”按钮。
- 无待保存修改时禁用保存按钮；权限发生变化后启用。
- 保存期间显示加载状态，并禁用权限勾选和重复提交。
- 仅提交权限发生变化的角色。

本次不增加角色、新增权限项、权限继承、批量回滚、离开页面确认弹窗或历史版本功能。

## 前端设计

`PersonnelPage` 管理角色权限编辑状态，包括服务端已保存快照、当前编辑值、加载状态和保存状态。`PermissionMatrix` 保持为受控的权限表格，只负责展示角色与触发单项权限变更。这样页面右上角的保存按钮与矩阵共享同一份状态，不使用跨组件命令或隐式事件。

`PermissionRole` 保留后端返回的角色 `id`。`PlatformService` 新增单角色权限更新方法，接收角色 ID 和完整权限对象并返回更新后的角色。API 服务将其映射到现有的 `PUT /roles/{role_id}/permissions`；模拟服务维护可变的角色集合，使组件重新加载角色时能读到已保存值。

页面通过比较当前权限与已保存快照识别发生变化的角色。点击保存后并发提交这些角色；全部成功时用服务端响应更新当前值和快照，并显示“角色权限已保存”。

## 数据流

```text
进入角色与权限页签 -> listRoles -> 已保存快照 + 当前编辑值
勾选权限 -> 只更新当前编辑值 -> 保存按钮启用
点击保存 -> updateRolePermissions(每个已修改角色)
         -> PUT /api/v1/roles/{role_id}/permissions
         <- 更新后的角色
保存成功 -> 更新快照和当前编辑值 -> 保存按钮禁用
```

## 错误处理

- 角色列表加载失败时继续显示现有加载失败空状态。
- 保存请求失败时显示“角色权限保存失败”，保留当前编辑内容和待保存状态，允许用户重试。
- 保存期间禁用矩阵勾选，避免请求中的权限数据与屏幕状态不一致。
- 多角色请求可能部分成功；失败后重新拉取角色列表，并将尚未成功保存的编辑值覆盖回当前状态，使用户可以再次保存剩余修改。

## 测试与验收

前端页面测试先覆盖显式保存行为：权限勾选后保存按钮启用，点击保存后出现成功反馈，再次加载角色列表仍返回已保存权限。服务层测试覆盖 API 请求路径、方法和请求体，以及模拟服务保存后的重新读取。

完成前运行人员管理页面测试、全部前端 Vitest、TypeScript 类型检查和生产构建。随后在浏览器中验证桌面和移动视口下按钮、权限矩阵横向滚动、加载状态和反馈消息没有重叠或溢出。

## 验收标准

- “角色与权限”页签显示保存按钮，“用户列表”页签仍显示添加用户按钮。
- 未修改权限时不能提交；修改后可一次保存所有变化。
- 保存成功后重新进入页面或刷新页面，权限值仍然保留。
- 保存失败不会丢失用户尚未保存的编辑内容，并可重试。
- 现有用户管理功能保持可用，前端测试、类型检查和构建通过。
