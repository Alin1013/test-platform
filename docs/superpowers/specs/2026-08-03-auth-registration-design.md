# 账号注册与后端认证设计

## 目标

在现有登录页底部增加注册入口，使用注册弹窗创建可持久化的账号，并让登录流程能够立即使用新账号。注册数据写入现有 SQLite `users` 表，不新增独立的用户表或管理端权限模型。

## 范围

- 登录页底部增加“立即注册”按钮，点击后打开注册弹窗。
- 注册字段为账号、姓名、邮箱、密码和确认密码。
- 前端在提交前校验必填项、邮箱格式、密码长度和两次密码一致性。
- 后端新增公开 `POST /api/v1/auth/register`，默认创建启用状态的“测试工程师”账号，部门为“质量保障部”。
- 账号和邮箱按规范化后的值进行唯一性校验，重复时返回 HTTP 409。
- 注册成功后关闭弹窗、回填登录账号并显示“注册成功，请登录”，不自动登录。
- 登录、注册、退出和个人资料更新通过统一认证客户端访问后端；测试环境保留内存客户端，避免组件测试依赖网络。

本次不实现邮箱验证、验证码、找回密码、自动登录、邀请链接或管理员审批。

## 后端设计

### 请求与响应

新增 `RegisterRequest`：

- `account`: 3-64 个 ASCII 字母、数字、下划线、短横线或点；服务端去除首尾空格并转小写。
- `name`: 1-64 个字符。
- `email`: 合法邮箱，转小写后保存。
- `password`: 8-128 个字符。

新增 `RegisterResponse`，返回创建后的 `AuthUserResponse`，不返回密码、密码哈希或会话令牌。

### 服务与路由

`backend/app/services/auth.py` 增加注册服务：查找默认角色“测试工程师”，创建 `User`，设置 `department="质量保障部"`、`status="enabled"`，使用现有 `hash_password` 保存凭据；提交时捕获账号或邮箱唯一约束冲突并转换为 409。

`backend/app/routers/auth.py` 增加 `POST /api/v1/auth/register`，复用现有认证 schema 和用户序列化逻辑。数据库模型和迁移无需变化。

## 前端设计

### 认证边界

新增认证客户端模块，定义登录、注册、退出和个人资料更新的传输接口。生产/开发客户端请求 `VITE_API_BASE_URL`，内存客户端仅用于 Vitest 组件测试并保留现有演示账号。`AuthContext` 通过可选客户端注入，统一管理异步提交状态、当前用户和会话令牌。

登录页在现有登录表单下方放置次级注册按钮。注册弹窗使用 `Form` 和 `Modal`，提交时显示按钮 loading；成功时 reset 表单、关闭弹窗、回填账号并展示成功提示。409 和其他网络错误以弹窗内的错误提示呈现，不丢失用户已填写内容。

## 数据流

```text
登录页 -> AuthContext.register -> AuthClient.register
       -> POST /api/v1/auth/register -> auth.register -> users(SQLite)
       <- AuthUserResponse         <- 注册结果
登录页 -> AuthContext.login -> AuthClient.login
       -> POST /api/v1/auth/login -> AuthSession(SQLite)
```

认证客户端只处理 HTTP 和响应映射，页面只依赖 `AuthContext`，避免页面直接拼接 API URL。后端持久化账号，当前会话令牌仍由内存状态管理；刷新后需要重新登录，但新账号不会丢失。

## 错误处理

- 前端表单规则阻止空值、非法邮箱、短密码和不一致的确认密码提交。
- 后端 Pydantic 校验错误返回 422，客户端映射为表单错误或通用错误提示。
- 账号/邮箱冲突返回 409，显示“账号或邮箱已存在”。
- 网络或服务端异常显示“注册失败，请稍后重试”，保留表单内容以便重试。
- 后端默认角色不存在时返回明确的 500 错误，测试种子数据保证正常环境包含该角色。

## 测试与验收

后端在 `backend/tests/test_auth.py` 增加公共 HTTP 边界测试：成功注册并能登录、重复账号/邮箱返回 409、无效字段返回 422。

前端在 `frontend/src/pages/login/LoginPage.test.tsx` 增加交互测试：打开注册弹窗、校验确认密码、成功注册后关闭并回填账号、冲突错误提示。认证客户端单测覆盖请求路径、JSON body 和错误响应映射；现有登录、个人资料和应用壳测试继续通过内存客户端运行。

完成前运行后端 pytest，前端 Vitest、TypeScript 类型检查、生产构建，并用浏览器在桌面和移动视口验证注册入口、弹窗布局、提交 loading、错误提示和成功回填无溢出或遮挡。

## 验收标准

- 未登录用户可在 `/login` 打开注册弹窗并完成合法注册。
- 注册账号可写入 SQLite，关闭或刷新页面后仍可使用同一账号和密码登录。
- 重复账号/邮箱和非法表单输入得到明确反馈，不会创建重复用户。
- 登录页和现有认证相关功能保持可用，前端测试、后端测试、类型检查和构建均通过。
